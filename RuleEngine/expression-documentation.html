Legal auctions, compact rules

Describe a family of bidding sequences once.

The rule engine compiles every expression into a legality-aware state machine. It learns symbolic suits, prunes concrete expansions that violate Bridge bidding order, and rejects expressions for which no legal auction exists.

Calls and learned symbols

FormMeaningExample
1C, 4NT, P, X, XXAn exact call. A bare X is double.1NT-2C
#DDiamonds at any independently selected legal level.1D-#D-4D
MA learned major: hearts or spades. Reusing M means the same suit.1M-2M
mA learned minor: clubs or diamonds. Case matters.1m-3m
X Y Z WDistinct learned non-NT suits, first introduced in that order.1X-2Y
Learning is persistent within one match. If 1X matches 1H, a later 2X can only match 2H. The # level is different: each occurrence is resolved independently.

Sequence syntax

A-B

Sequence

Match A followed by B.

(A|B)

Alternative

Match either branch. Non-capturing form (?:A|B) is accepted.

*

Zero or more

Match zero or any finite number of arbitrary legal calls.

?

One or more

Match one or any finite number of arbitrary legal calls. This intentionally differs from JavaScript RegExp.

^A

Opponent call

Require A to be called by an opponent. It may prefix a call, wildcard, or group, such as ^2C or ^(2C|2D); it is a role marker, not a start-of-string anchor.

System-side expressions are compact by default. Without ^, opponent calls are omitted before matching. When an expression contains ^, it reads the full auction in turn order: unprefixed atoms belong to the selected system partnership and prefixed atoms belong to its opponents. For example, 1S-^2C-2H matches a 1S opening, an opponent's 2C overcall, and partner's 2H response.

Predicates, arithmetic, and order

A predicate group matches one contract bid. For example, (?:!=NT)-4NT recognizes 4NT after any suit contract, but by itself does not prove that partner agreed that suit. Denominations support = and !=; concrete contract operands also support <, >, <=, and >=.

Contract arithmetic follows the 35-step ladder from 1C through 7NT, so 1D+5=2D is true. A rule's where relations can compare learned suits: Y<X means Y has lower denomination rank than X.

Worked examples

1D-#D-4D

Compiles to exactly 1D-2D-4D and 1D-3D-4D. Other levels make one of the neighboring calls illegal.

1C-1X-3NT

The middle call can be 1D, 1H, or 1S. Clubs repeat the current contract and NT is not a symbolic suit.

1X-2Y with Y<X

Describes the six natural 2/1 new-suit responses: 1D–2C; 1H–2C/2D; and 1S–2C/2D/2H.

*-#X-*-#X-*-4NT

Finds two calls in the same learned suit anywhere before 4NT. Add "requiresAgreement": ["X"] to require those suit calls to come from both members of the partnership, rather than one player rebidding the suit.

System JSON

Place reusable expressions in the system's top-level sequenceRules array:

{
  "id": "two-over-one",
  "expression": "1X-2Y",
  "where": ["Y<X"],
  "meaning": "2/1 game force",
  "priority": 100
}
{
  "id": "explicit-fit-blackwood",
  "expression": "*-#X-*-#X-*-4NT",
  "requiresAgreement": ["X"],
  "meaning": "Blackwood after explicit suit agreement",
  "priority": 120
}

SystemBuilder checks each rule as you type. An overlap is reported with a concrete legal witness. An overlap with different meanings at the same priority is an inconsistency; a different priority is reported as a warning because resolution is deterministic.

Engine API

const rule = BridgeBiddingEngine.compileSequenceExpression("1C-1X-3NT");

rule.expand();       // concrete legal sequences
rule.match(calls);   // search a contiguous segment
rule.matchExact(calls);
rule.next(calls);    // legal calls that advance or complete the rule

BridgeBiddingEngine.addToContractBid("1D", 5);       // "2D"
BridgeBiddingEngine.evaluateBidRelation("1D+5=2D"); // true
BridgeBiddingEngine.findSequenceOverlap("1M", "1H"); // ["1H"]
